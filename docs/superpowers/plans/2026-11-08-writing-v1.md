# 猛犸写作 V1.0 最小可用版实施计划

> 执行方式：当前任务内实施与独立场景检查。只修改 dev-writing，不新建分支或 worktree，不推送、不发布。

**目标：** 在现有中文写作基础上，提供可直接使用的独立创作与创作仓库托管规则，先让猛犸使用，再根据实测迭代。

**结构：** 保留 human-writing 的名称和通用参考文件。入口补充创作责任；视频方法放在 formats.md；托管、交接和轻量经验放在一个 workspace.md；精简版可脱离安装独立使用。

**技术：** Markdown / YAML，无新增服务、数据库或运行依赖。

**需求来源：** 用户本轮讨论与开始实施指令；范围落入 docs/PROJECT.md，长期决定落入 docs/DECISIONS.md。

## 边界

- 培养独立作者与合作默契，不拟合猛犸画像；现有可接受稿件不是审美上限。
- 主要服务自媒体视频文案，同时保留其他文体和事实/虚构边界。
- 用户创作目录与 skill 源码目录分开，由 Agent 维护 AGENTS.md 和当前文件入口。
- 通用对话性格由用户已有个性化指令处理，不另做情绪系统。
- 不做工作台、自动学习数据库、自动部署或强制逐阶段审批。

- [x] 修改 SKILL.md、formats.md、revision.md；新增 workspace.md。

- [x] 在隔离临时目录执行新版实际落盘与接手场景，检查文件与回复。
- [x] 检查反馈经验是否有情境依据、能否保留不同创作选择；检查无文件工具时是否诚实降级。
- [x] 校验引用路径、元数据和 diff；保存有限验证结果与仍需真实用户测试的项目。

## 审查重点

1. 改稿后局部和全文是否一致，是否保留用户手写内容与可恢复版本。
2. 换 Agent 后能否定位实际当前稿、待处理问题和已经决定的内容。
3. 一次否定会不会变成所有作品的禁令，经验会不会成为迎合的标准。
4. 精简版没有外部参考时是否仍足够使用；无文件权限时不得声称落盘。
5. 文档链接要指向真实文件；当前客户端实际打开和保存仍需真人实测。

## 验证范围

本轮是规则与有限行为场景检查，不证明文学质量、长期独立性或所有模型的一致表现，不替代猛犸的首轮真实创作。

## 首轮反馈：建目录授权与系列归档

用户要求首次由 Agent 引导决定根目录位置和名称，完整路径获用户授权后创建；已有目录则确认使用。系列按共享资料与各期作品区分，例如说文解字每期一个字，不预设总期数。
