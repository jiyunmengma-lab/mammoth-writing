# V1.0 候选规则验证记录

日期：2026-11-08。验证只针对当前 dev-writing 工作树，不是猛犸真实创作验收。

## 基线

修改前用原 skill 执行一个独立场景：在临时创作目录写约一分钟的虚构示例口播，另建空白结尾文档，并给下一位 Agent 留下接续信息。

实际创建了稿件、0 字节空白文件和 AGENTS.md；能够独立成稿并保留虚构边界。最终回复列出文件名，但没有给可点击入口。AGENTS.md 明确写着“这里只记录本次作品，不建立长期作者画像或全局写作规则”，反映原规则只服务当前作品的范围。

基线最终回复原文（文件列表另列）：

> 口播稿写好了，约一分钟，示例已明确标为虚构，也有完整结尾。
>
> 另外留了一份完全空白的《我的结尾》，方便你自己写；交接说明也已放好，以后换一个 Agent 可以接着工作。

## 包装检查

`ruby tests/check_package.rb` 验证 skill 和 UI 元数据、参考路径、Markdown 本地链接以及直接使用版不依赖外部参考文件。此检查不评价创作行为。

系统 skill-creator 的 Python 校验器尝试运行时缺少 PyYAML；没有为此修改用户 Python 环境，使用系统 Ruby 的 YAML 解析器完成上述检查。

## 候选版场景

场景原始请求与可复跑步骤见 `tests/scenarios.md`。临时执行产物集中在系统临时目录，不放入实际创作资料或 skill 运行目录。

### 直接使用版：情境变化与无文件能力

独立 Agent 只读取 lite，在没有文件能力、没有外部资料的情境中回答。实际回复反对“宇宙终极秘密”这种与字形差异不匹配的开头，建议用核实过的古今字形对照继续讨论；没有整篇重写或虚构史实。明确指出上期删背景的原因是观众已知，不能变成以后都不讲背景。

其接续记录明确标为“目前未保存到文件”，将本期建议记为尚未决定、字例仍需核实。这次观察符合讨论、事实边界和情境经验要求；不证明其他请求也会稳定做到。

### 文件托管与新 Agent 接手

新版场景实际创建了按作品收纳的完整稿、0 字节用户自写文档和根目录 AGENTS.md。Agent 最终回复提供两个指向实际文件的链接，说明时长只是估计。交接文件注明了规则位置、材料边界、当前稿、用户自写入口和下一步，没有建立空的经验数据库。

文件存在与内容已独立复核。客户端点击打开尚未验证。

在用户自写文档中加入一段模拟结尾后，由全新 Agent 只根据创作目录接手：找到了规则与当前稿，逐字保留用户结尾并调整前文铺垫，保留原始自写文件，改写前保存了完整历史稿，继续使用同一个当前稿入口，并将 AGENTS.md 更新为暂停状态。

已复核实际文件并用断言确认：用户原文未改；结尾进入当前稿；历史稿保留原结尾且不含新结尾；交接状态为暂停。最终回复给当前稿链接。没有外部检索或真实用户编辑参与。

## 尚未验证

- 猛犸当前客户端点击文档、亲自编辑、保存回原文件的完整链路。
- 多模型表现、长对话中的稳定性和跨作品的长期独立性。
- 重复抽样对照；有限单次场景不能证明效果普遍优于原版。

不以这些未完成项目阻止候选规则供试用，也不将其包装为已通过验收。
