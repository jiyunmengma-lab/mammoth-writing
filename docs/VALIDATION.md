# V1.0 候选规则验证记录

日期：2026-11-08。验证只针对当前 dev-writing 工作树，不是猛犸真实创作验收。

## 基线

修改前用原 skill 执行一个独立场景：在临时创作目录写约一分钟的虚构示例口播，另建空白结尾文档，并给下一位 Agent 留下接续信息。

实际创建了稿件、0 字节空白文件和 AGENTS.md；能够独立成稿并保留虚构边界。最终回复列出文件名，但没有给可点击入口。AGENTS.md 明确写着“这里只记录本次作品，不建立长期作者画像或全局写作规则”，反映原规则只服务当前作品的范围。

基线最终回复原文（文件列表另列）：

> 口播稿写好了，约一分钟，示例已明确标为虚构，也有完整结尾。
>
> 另外留了一份完全空白的《我的结尾》，方便你自己写；交接说明也已放好，以后换一个 Agent 可以接着工作。

## 包装检查

`ruby tests/check_package.rb` 验证 skill 和 UI 元数据、参考路径、Markdown 本地链接以及直接使用版不依赖外部参考文件。此检查不评价创作行为。

系统 skill-creator 的 Python 校验器尝试运行时缺少 PyYAML；没有为此修改用户 Python 环境，使用系统 Ruby 的 YAML 解析器完成上述检查。

## 候选版场景

场景原始请求与可复跑步骤见 `tests/scenarios.md`。临时执行产物集中在系统临时目录，不放入实际创作资料或 skill 运行目录。

### 直接使用版：情境变化与无文件能力

独立 Agent 只读取 lite，在没有文件能力、没有外部资料的情境中回答。实际回复反对“宇宙终极秘密”这种与字形差异不匹配的开头，建议用核实过的古今字形对照继续讨论；没有整篇重写或虚构史实。明确指出上期删背景的原因是观众已知，不能变成以后都不讲背景。

其接续记录明确标为“目前未保存到文件”，将本期建议记为尚未决定、字例仍需核实。这次观察符合讨论、事实边界和情境经验要求；不证明其他请求也会稳定做到。

### 文件托管与新 Agent 接手

新版场景实际创建了按作品收纳的完整稿、0 字节用户自写文档和根目录 AGENTS.md。Agent 最终回复提供两个指向实际文件的链接，说明时长只是估计。交接文件注明了规则位置、材料边界、当前稿、用户自写入口和下一步，没有建立空的经验数据库。

文件存在与内容已独立复核。客户端点击打开尚未验证。

在用户自写文档中加入一段模拟结尾后，由全新 Agent 只根据创作目录接手：找到了规则与当前稿，逐字保留用户结尾并调整前文铺垫，保留原始自写文件，改写前保存了完整历史稿，继续使用同一个当前稿入口，并将 AGENTS.md 更新为暂停状态。

已复核实际文件并用断言确认：用户原文未改；结尾进入当前稿；历史稿保留原结尾且不含新结尾；交接状态为暂停。最终回复给当前稿链接。没有外部检索或真实用户编辑参与。

## 首轮反馈：首次目录授权与系列归档

原版首次回复为：“可以。你想把‘说文解字’系列的创作目录放在哪里？比如桌面或‘文稿’文件夹里。确定位置后，我来创建和整理。”未执行文件写入，但未引导决定目录名称，也未明确完整路径的创建授权。

补充规则后的独立场景：

- 完整版首次无目录：询问父目录和名称，给名称建议，并说明会展示完整路径、等确认后创建；检查测试目录仍为空。
- 直接使用版仅给父目录：建议新目录名，列出组合后的完整路径并询问是否创建；检查测试父目录仍为空。
- 明确批准完整路径后的系列归档：实际只建立获准的测试根目录、说文解字共享资料以及“我”“贞”两期资料。共用资料只保存一份，各期引用；问题保持待查状态，没有空稿或预建未来各期。复核全部文件及 5 个相对链接，并以断言确认目录范围、共享资料数量与无空稿。已有目录的确认/复用规则已核对，未另作运行场景。

上述测试仅使用隔离临时目录，没有为真实用户创建创作目录。

## 本机地址簿：跨新会话定位

在独立临时目录中模拟 HOME，地址簿指向一个真实的测试创作目录，其中 AGENTS.md 指向实际 current.md；另一个空目录作为会话工作目录。没有读取或修改真实用户地址簿。

基线 Agent 仅获得旧 skill、模拟 HOME、空工作目录及“继续之前的写作，给我当前稿入口，先不要改”，没有创作路径提示。它读取规则后查看空工作目录，回复：“这次会话里还没有之前写作目录的位置。把目录路径发我，我就只核对当前稿并给你入口，先不改文件。”没有发现地址簿。

新版全新 Agent 在相同条件下实际读取约定的地址簿，校验 JSON 与唯一绝对路径，确认根目录可访问，读取 AGENTS.md 和当前稿，返回正确文件链接和“下一步只讨论结尾”的接手状态，没有修改文件。实际稿件随后复核未变。该测试验证独立 Agent 上下文中的规则执行，不是用户在 Codex 界面中新建会话的完整端到端测试，也未验证链接点击。

包装检查新增完整参考与直接使用版地址簿协议完全一致的比较。它只能发现分发文本漂移，不能替代上述行为测试。

直接使用版另作五项模拟故障判断：地址簿 EACCES、本地目标 ENOENT、外置卷已确认未挂载、JSON 损坏、两个有效候选无法确定。独立 Agent 分别选择请求必要读取权限、询问搬移位置、请用户连接磁盘、保留原文件并确认修复、让用户选目录；没有把失败视为空表，也没有建议擅自重建或覆盖。审查完整参考与 lite 未发现实质分歧。

权限与卷状态是测试者提供的模拟结果，未实际触发客户端权限弹窗、拒绝/批准、拔插磁盘或系统级访问错误；不能据此声称这些客户端链路已跑通。真实界面中新会话的 skill 加载、不同 Agent 与不同沙箱配置也待试用。

直接使用版首次登记实测：另一个隔离模拟 HOME 中已有旧创作室记录，用户当次明确批准在不同完整路径创建新创作室并登记。独立 Agent 实际建立新目录的 AGENTS.md，保留旧条目，按完整路径加入新条目，使用同目录临时文件替换并回读。随后独立断言确认两条名称与路径准确、没有重复新记录、有接手入口且没有临时文件遗留；文件清单确认未创建空稿或作品目录。尚未选题的状态没有被旧记录覆盖。
