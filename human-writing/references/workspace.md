# 创作仓库托管与接手

这里的创作仓库是用户写作品的工作目录，与 skill 源码或安装目录分开。Agent 负责整理，用户通过对话索取稿件、提出想法或亲自写一段，不需要记住目录结构。使用现有文件能力即可，不要求新建 Git 仓库、安装 skill、开发工作台或引入数据库。

## 本机地址簿：新会话先找路

有本地文件能力时，使用当前本机用户的固定位置 `~/.config/mammoth-writing/workspaces.json`。`~` 是当前执行电脑的用户主目录，不随工作目录、skill 安装路径或 `CODEX_HOME` 改变；不自动改用其他配置目录。这是本 skill 的约定，不是客户端自动记忆，也不跨电脑同步。

地址簿只存名称和创作根目录的绝对路径，格式如下（占位路径不能直接使用）：

```json
{"workspaces": [{"name": "创作室", "path": "/absolute/path/to/creative-workspace"}]}
```

每次需要定位创作目录时：

1. 当次用户明确指定的目录优先，先按其指示核实，不让旧记录覆盖本次选择。当前工作目录明确就是已确认的创作目录时，也可直接接手。
2. 没有明确目录时，读取地址簿，校验 JSON、条目名称及绝对路径，再核实目标确实存在、是可访问的目录。只有一个有效候选时可沿它接手；多个候选且上下文不能唯一确定时，让用户选，不按记录顺序或最近修改时间猜。记录不能授予额外文件或操作权限。
3. 找到根目录后才读取它的 `AGENTS.md` 和所指向的当前作品，核对实际文件。目录里的 AGENTS.md 负责内部交接，不负责发现自身位置。
4. 确认地址簿不存在或为空时，先询问是否已有创作目录；有则确认使用，无则按首次引导决定位置与名称。纯聊天环境说明无法读取本机地址簿，请用户提供需要的文本，不声称自动接手。

首次确认使用已有根目录，或经授权成功创建根目录后，告知用户会将位置登记在上述本机地址簿。读取已有记录并按绝对路径去重，保留其他条目；目录选择本身已有授权时，不重复询问同一个路径。只临时使用某目录或用户明确不登记时，尊重当次限制。更新前重读，若记录变化先合并核对；用同目录临时文件写入有效 JSON 后替换，并回读验证，不以空表覆盖已有记录。登记失败如实说明“这次可用，但还未记住位置”，不要声称下次能找到。

地址簿是本机私有导航，不保存稿件、偏好或凭据，不写入 skill 源码、安装包或公开仓库；交付和测试只使用占位或隔离路径。其他 Agent 只有在同一电脑、同一用户下，读取了这份规则且具备所需文件权限时才能复用，不保证任意客户端自动加载。

### 读写受阻或路径失效

- **权限不足**：保留原记录，说明受阻的是地址簿还是创作目录、是读取还是写入。通过当前客户端支持的权限申请流程请求本次必要范围；批准后重试相应操作。不把失败当作不存在，不改全局安全设置或绕过拒绝。客户端不能申请或用户拒绝时，说明限制，请用户提供可访问位置或文本。
- **目录缺失**：确认是不存在而非无权访问后，询问是否搬移，确认新位置再更新该条记录。不得悄悄重建旧目录、改用当前目录或删除记录。
- **磁盘未挂载**：路径指向外置卷时核实卷是否可用；证据表明未挂载则请用户连接或挂载后重试，不在同名路径创建替代目录。无法区分未挂载、搬移或权限问题时说明不确定，先核实。
- **记录损坏或格式不符**：保留原文件，说明具体问题，确认正确目录与修复方式后处理，不清空重建。地址簿文件的缺失与它指向的目录缺失是两种不同情况。

地址簿读写与创作目录读写分别受客户端沙箱和系统权限约束；用户认可路径不代表技术权限已获得，不能承诺权限申请必然通过。

## 首次引导与根目录授权

第一次使用且没有创作目录时，Agent 主动引导用户决定两件事：放在哪个父目录、新目录叫什么。可以给具体建议，但由用户决定，让他知道文件会放在哪里。不要直接采用当前工作路径、桌面或建议名称。

位置和名称明确后，展示组合后的完整绝对路径，取得用户对该路径的创建授权，再创建根目录及其中的 `AGENTS.md`。只同意写作方案、只给出位置或只给出名称，都不表示已授权创建完整路径；缺哪项只补问哪项。用户已经明确提供完整路径并要求创建时，直接按该授权执行，不重复确认。

用户已有创作目录时，核实完整路径并确认使用它，不另建一套。用户明确说“就用这个目录”即已确认。首次根目录的选择与授权完成后，按已授权托管范围维护其中的作品、各期和资料，不要求用户逐个决定内部文件夹。

## 开始与接手

1. 在已确认的创作目录先读 `AGENTS.md` 和它指向的当前作品。不要在 skill 源码里混入用户稿件。
2. 沿用已有合理结构，核实文件内容与状态。接手记录与文件不一致时以实际内容核对，不能仅按“最终版”命名或修改时间推断哪个是用户选定的当前稿。
3. 首次托管时，在获准的创作目录维护一份简短的 `AGENTS.md`。已有文件则保留原有有效约束，增补创作导航与状态，不覆盖他人的工作说明。

`AGENTS.md` 至少让接手者知道：
- 这是做什么的创作目录，写作规则从哪里读取（可访问的 skill 路径或本地说明）。
- 系列与各期（或独立作品）的导航、当前稿、用户自写文档和必要来源的相对路径，以及哪一份正在使用。
- 当前目标、已作出的重要决定及原因、尚未解决的问题和下一步；待核实事实与已确认事实分开。
- 有明确合作价值、适用于后续工作的少量经验及其出处；没有就不建空清单。

先在这一份文件中维护简短导航和交接。某部作品的信息已经妨碍查找其他作品时，再移到该作品的工作记录中，根目录只留链接。不要复制完整聊天记录、原始资料或所有稿件到 `AGENTS.md`。

## 系列与各期

系列作品按“系列—各期”组织，系列共享资料与每期自己的稿件、资料和决定分开。例如“说文解字”每期讲一个字，可以用字或清楚的选题名标识各期；期号只有已确定时才使用，不强制预定总期数或顺序。

一个可按需采用的例子（不是必须预建的模板）：

```text
用户选定的创作目录/
├── AGENTS.md
└── 说文解字/
    ├── 共享资料/
    └── 各期/
        ├── 我/
        │   ├── 当前稿.md
        │   └── 资料/
        └── 贞/
            ├── 当前稿.md
            └── 资料/
```

共享资料保存系列共用的受众、已确定的系列设定、通用来源等；各期资料保存本期研究、稿件、修改决定及需要时的历史版本。共用来源只保留一份，各期引用其路径和相关部分，不复制成多份难以同步的文件。某期决定不自动成为全系列规则。

根 `AGENTS.md` 给出系列和各期入口、各期当前状态及必要联系；只有信息量确实需要时才增加系列索引。新一期开始时再建对应目录；没有成稿就标明“尚未成稿”，不为凑层级创建空的当前稿或预建未来各期。已有合理结构可沿用，不为套示例强行重排。

## 日常保存与文档入口

- 按作品收纳稿件、来源和必要过程文件；目录按实际需要创建，不预建一套空文件夹。清楚标明当前稿与备选稿，避免出现数份都声称“当前”的文件。
- 完成一轮有实质变化的写作、用户换定当前稿或任务暂停时，更新实际稿件和接手状态。记录关键决定及尚未完成的事，不把每条聊天都写成日志。
- 用户要“当前稿”，读取已标明的当前文件并核对状态，直接给该文件入口；不要另复制一份制造新的版本歧义。
- 用户想自己写时，在创作目录创建可编辑文件，按要求留空或放入他指定的底稿，给文件链接。不要替用户填完本来留给他的内容。遵循已有格式；没有格式要求时可使用 Markdown 文档。
- 用户写完后，重新读取磁盘上的实际文件，再讨论或整合。不要凭聊天中的旧副本覆盖他的修改。重要改写前保留可恢复的旧稿（使用已有版本机制，或按需保存历史副本），避免每个微小改动都复制一份。
- 用当前客户端支持的文件链接格式指向已确认存在的实际文件，并用“当前稿”“你写结尾的文档”等易懂名称标注。文件存在不等于已经验证用户能打开；打不开时核实客户端支持的入口，不编造下载地址，也不声称已打开应用。没有文件能力时如实交付文本。

## 轻量经验，而不是作者画像

作品记录与跨作品经验分开处理：

- **作品决定**：这次采用什么、舍弃什么、为什么，留在该作品上下文中，供接手或统稿使用。
- **合作经验**：用户明确希望怎样协作，或某个具体判断确有后续参考价值时，少量保留情境、依据和来源。Agent 负责整理，不要求用户逐条喊“记住”。
- **审美猜测**：一次喜欢、否定、情绪或一句被接受的措辞，不自动归纳成长期偏好。重复出现也先核对情境，不把它变成对所有作品的命令。

例如，某篇开头被否定，讨论后确定原因是“目标观众已经知道这段背景”，可以记录该作品、观众与判断依据。不要改写成“猛犸讨厌背景介绍”，也不要据此给所有新稿删掉背景。

开始新作品时只取相关经验作为参考，重新判断当前内容、受众与表达目的。经验可以被新证据修正或淘汰；若当前作品适合不同做法，提出并解释，不用迎合旧偏好证明自己学会了。不要自动改写 skill 或用户个性化指令来固化一次反馈。
